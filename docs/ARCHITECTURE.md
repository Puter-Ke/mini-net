# 架构与设计决策

> 每个模块都要写清三件事：**它解决什么问题 / 为什么这样设计 / 代价是什么**。
> 面试官考察的是第三点。

## 模块图（M3 之后的样子）
```
                 main thread                    sub threads
  ┌──────────────────────────┐      ┌───────────────────────────────┐
  │ EventLoop(main)          │      │ EventLoop #1  (epoll + timer) │
  │  └─ Acceptor(Channel)    │─────▶│ EventLoop #2                  │
  │      round-robin 分发     │      │ EventLoop #3                  │
  └──────────────────────────┘      └───────────────────────────────┘
           每个连接固定绑到一个 loop（避免锁），跨线程用 runInLoop 投递 + eventfd 唤醒
```

## 决策记录（边做边填）
| 决策 | 选择 | 为什么 | 代价 |
|---|---|---|---|
| IO 模型 | epoll ET + 非阻塞 | 少一次事件通知，高并发下 syscall 更少 | 必须一次读到 EAGAIN，代码复杂度上升 |
| 线程模型 | one loop per thread | 连接与线程绑定，几乎不需要锁 | 负载不均（热点连接）；线程数不能太多 |
| 缓冲区 | 环形 Buffer + readv | 减少拷贝与扩容次数 | 实现复杂，指针生命周期要小心 |
| 内存 | 自写定长对象池 | 降 malloc 次数与碎片 | 只适合固定大小对象，通用性差 |
| 定时器 | 时间轮 | O(1) 插入/删除，海量连接友好 | 精度受 tick 限制 |
