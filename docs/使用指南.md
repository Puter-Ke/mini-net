> 项目地址：https://github.com/Puter-Ke/mini-net
>
> **先记住一件事**：这个项目是 Linux 程序（用的是 Linux 的 epoll）。

## 方式二：在浏览器里把它跑起来（推荐，不用装任何软件）

这就是"用"这个项目的最省事方式 —— 借用 GitHub 免费送的云端 Linux 机器。

### 第 1 步：打开 Codespace（约 3 分钟）

1. 浏览器打开 https://github.com/Puter-Ke/mini-net
2. 点右上角绿色的 **`< > Code`** 按钮
3. 切到 **Codespaces** 标签 → 点 **Create codespace on main**
4. 等 1~3 分钟（它在云端给你开一台 Linux 机器，并自动装好 g++ / cmake / gdb / valgrind）

> 你看到的是一个**浏览器版的 VS Code**。左边是文件树，右边是编辑器，下面可以开终端。
> 免费额度：个人账号每月 60 小时（2 核机器），够你学习和演示很多次。

### 第 2 步：编译（约 1 分钟）

在 Codespace 里打开终端：菜单 **Terminal → New Terminal**（或按 `` Ctrl+` ``），然后粘贴：

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

看到最后一行不再滚动、没有红色 `error` 就是编译成功。

### 第 3 步：启动服务

```bash
./build/mini_net_server 8080 30 4
```

三个参数分别是：**端口 8080**、**空闲超时 30 秒**、**IO 线程数 4**。

看到这两行就是启动成功（终端会"卡住"不返回，这是正常的 —— 服务正在运行）：

```
[INFO] 服务启动：0.0.0.0:8080，IO 线程 4，空闲超时 30 秒
[INFO] mini-net 短链服务就绪：http://127.0.0.1:8080（IO 线程 4，空闲超时 30 秒）
```

**想停止服务**：在这个终端里按 `Ctrl + C`。

### 第 4 步：开始用它（新开一个终端，别关掉运行服务的那个）

点终端面板右上角的 **`+`** 新开一个终端，然后一条一条粘贴执行：

**① 健康检查**
```bash
curl -i http://127.0.0.1:8080/healthz
```
预期：`HTTP/1.1 200 OK`，最后一行是 `ok`

**② 创建一个短链**（把长网址变短）
```bash
curl -i -X POST http://127.0.0.1:8080/api/shorten -H 'Content-Type: application/json' -d '{"url":"https://www.huawei.com/cn/"}'
```
预期：`HTTP/1.1 201 Created`，返回体里有 `"code":"V0q"` 这样的短码，例如：
```json
{"code":"V0q","short":"http://127.0.0.1:8080/V0q","url":"https://www.huawei.com/cn/"}
```

**③ 访问短链（这就是"别人用你的服务"的样子）**
```bash
curl -i http://127.0.0.1:8080/V0q        # 把 V0q 换成上一步返回的真实短码
```
预期：`HTTP/1.1 302 Found` + `Location: https://www.huawei.com/cn/`

**④ 看统计（这个短码被点了几次）**
```bash
curl -i http://127.0.0.1:8080/api/stats/V0q
```
预期：`{"code":"V0q","url":"...","hits":1,"created_at":...}`

**⑤ 看服务自身指标**
```bash
curl -s http://127.0.0.1:8080/metrics
```
预期：
```
uptime_seconds 42
alive_connections 1
total_connections 5
total_bytes_in 620
total_requests 4
shorten_total 1
redirect_total 1
```

**⑥ 重复创建同一个网址** —— 会返回**同一个短码**（幂等，练习题：想想为什么这样设计）

### 第 5 步（可选）：让外网也能访问，发给朋友看

1. 在 Codespace 里找到 **PORTS** 面板（底部终端旁边，或菜单 View → Ports）
2. 看到 8080 那一行 → **右键 → Port Visibility → Public**
3. 复制它给出的网址（形如 `https://xxxxx-8080.app.github.dev`）
4. 把这个网址发给任何人，他们就能用你的短链服务了 —— 在浏览器里打开 `https://xxxxx-8080.app.github.dev/<短码>` 就会跳转

> 注意：关掉 Codespace 后这个网址就失效了。想长期在线，看下面的方式三。

### 用完记得停机（省免费额度）

Codespace 页面左下角 → **Codespaces: Stop Current Codespace**，或者直接关掉浏览器标签；
下次要用时从 https://github.com/codespaces 重新打开，或者干脆删掉重建。

## 常见问题（小白版）

**Q：`cmake: command not found`？**
A：说明你不在 Codespace 里，而是在自己的 Windows 终端。回到方式二的第 1 步。

**Q：`Address already in use`（端口被占）？**
A：上一次的服务还在跑。换个端口启动即可：`./build/mini_net_server 8081 30 4`（后面的 curl 命令也要把 8080 改成 8081）。

**Q：终端卡住不动了？**
A：那是服务在运行，正常现象。按 `Ctrl + C` 停止，或另开一个终端做别的操作。

**Q：想跑测试看看它有多可靠？**
```bash
ctest --test-dir build --output-on-failure     # 49 个单元/集成测试
bash scripts/smoke_test.sh 8081                 # 冒烟：HTTP + 1000 并发 + fd 泄漏检查
```
预期：测试全部 `Passed`，冒烟脚本打印 `通过 12 项，失败 0 项`。

**Q：我想改代码怎么办？**
A：在 Codespace 里直接改，改完重新 `cmake --build build -j` 再启动即可。改完想提交：
```bash
git add -A && git commit -m "我的修改" && git push
```
（第一次 push 会要求登录 GitHub，按提示授权或用 `gh auth login`。）

## 给面试用的三个动手练习（做完你就真的懂了）

1. **亲手看 ET 的坑**：把 `src/TcpServer.cc` 的 `handleAccept()` 里那个 `while (true)` 循环改成只 accept 一次，
   重新编译启动，然后用脚本同时连 50 个连接，观察有多少连不上。看完改回来。
2. **加一个统计接口**：在短链服务里加 `GET /api/total`，返回一共存了多少条短码（提示：`ShortUrlService::size()`）。
3. **给 send 加写缓冲**：现在响应小、一次就写完了；试着发一个很大的响应，观察 `TcpServer::flushWrite()` 里的写缓冲和 `EPOLLOUT` 是怎么起作用的。

做完这三个，`docs/面试准备.md` 里的 22 个问题你就有底气了。
